indexing pipeline

cold-start: turn a folder into a graph
scan          walk tree, honor gitignore + denylist
   ↓
prune         drop rows for files no longer on disk
   ↓
for each file:
  parse imports  resolve specifiers → file-to-file edges
   ↓
classify      framework detector hits ? use it : heuristic
   ↓
reconcile     diff with DB; preserve user-edited names
   ↓
aggregate     fingerprint match → cache; else → call LLM
   ↓
stats         files · edges · modules · status

edges

one import → one file-to-file edge
drawn
relative imports within the project
resolved against disk
skipped
third-party packages — noise
type-only imports — gone at runtime 
write strategy: replace all edges from this file, then insert new ones
→ no ghost lines, only one file affected per change

module discovery & naming

heuristics decide structure · LLM only labels
group by top-level folder
   ↓
folder is an outlier (statistical, large) → drill into second level
   ↓
buckets with too few files → fold back into parent
   ↓
collect frequent export names → hint card for the LLM
   ↓
fingerprint = hash(bucket names + member files)
   ↓
matches cache → reuse stored names   (zero LLM cost)
otherwise     → ask LLM for human name + one-line description
on failure    → fall back to bucket name   (visibly degraded)

three channels, one port

request · push · terminal
browser
   │
   ├─ HTTP           read snapshots, trigger user actions    "press button"
   ├─ push channel   receive "data changed", then refetch    "doorbell"
   └─ terminal       stream keys ↔ stream output             "video call"
                       ↓
              one HTTP server, routed by URL
                · tiny per-endpoint handlers, direct queries, no layers
                · push channel broadcasts a tag; clients refetch on demand
                · terminal channel spawns a Claude TUI process per connection

embedding the terminal

a real CLI inside the browser
browser                         server                          kernel
───────                         ──────                          ──────
terminal emulator                                               pseudo-terminal
  screen buffer    ←── output bytes (colors, cursor) ─── child stdout
  ANSI parser                                                     ↑
  key 'h'          ─── 'h' raw byte ──────────────────── child stdin

  resize observer  ─── {resize, cols, rows} ─────────→ tell kernel + signal child

server is byte-transparent: never parses ANSI, just shuttles streams
cleanup is two-way: closing the browser kills the child; child exit closes the socket

live loop

three listeners → one push channel → browser
filesystem watcher   disk changed         → reparse one file, broadcast update
CC hooks             Claude announces it    → broadcast pending / done
                     pre / post / start / stop, <300ms, fire-and-forget
heartbeat poller     1s pid liveness check  → broadcast session-dead
                     catches hard exits the hooks miss

why three? none alone is reliable.
  · hooks are clean but a force-kill skips them
  · watcher is accurate but identity-blind
  · poller is the safety net

AI provider & turn summary

user's own Claude CLI · grouped per module
AI provider     one method: complete(prompt) → text
                backed by the user's installed Claude binary
                zero config · reuses their plan · cancellable

turn tracker    state machine over the hook stream
                pre   → mark a tool in flight
                post  → record change · debounce idle window
                stop  → flush, mark final

orchestrator    on each flush:
                · group changes by top-level module
                · one parallel LLM call per module (with co-touched context)
                · store summary + broadcast tag
                · on failure: visible degraded line, never silent
